## 1. 一句话定义
把旧 MacCMS（`php/`，PHP + ThinkPHP 5.0）还没迁到 Java 的功能继续迁完；前台页面的模板以 PHP 模板（MacCMS 标签语法的 `.html`）为准，本期固定为 MacCMS 官方 `v2020.1000.1035` 的 `default_pc` + `default_wap`，对照用的 PHP 代码是仓库 `php/` 的 `2023.1000.3051`；全程不动数据库表结构，Java 按原表、原字段、原数据语义读写。

## 2. 背景与问题
- 现状（v6 清单已确认）：B01～B29 的 Java 代码大多已在 main，但前台页面是**重新写的 jte 页面**（`src/main/jte/site/…`），不是 PHP 模板；路线图当时的决定是“改写，不做兼容层”（`docs/architecture/09-roadmap.md` 第 2 节，03 草稿第 4.7 节“甲”方案）。
- 发起人 2026-10-30 的新方向与它冲突：前台模板要以 PHP 模板为准，也就是 Java 要能直接读取并渲染 MacCMS 模板（`{maccms:vod …}`、`{$obj.vod_name}`、`{include file=…}` 这类语法）。这在路线图里属于未做的“乙”方案（03 草稿第 4.7 节：兼容层，前期成本高）。
- **模板源文件不在仓库里，且官方同版本包也没有模板**：`php/template/` 下只有一个 0 字节的 `php/template/default/html/index.html`；备份 zip 里也一样（`AGENTS.md` 第 15 行、`09-roadmap.md` D9-a）。v5 的 OP-1 曾定为“用与 `php/` 同版本的官方默认模板”，但官方 `v2023.1000.3051` 标签的 `template/` 只有 3 个文件（`default/html/index/index.html` 一页说明、`default/html/public/verify.html` 验证码页、一份 txt 说明），没有 `{maccms:…}` 模板、手机模板和 `ads/`；`v2021.1000.1081` 起同样不再带模板。所以发起人在评论 `01a1917b-3354-7551-9a4e-cee858f5e07a` 重新决定：模板用最后一个仍带完整模板的官方版本 `v2020.1000.1035` 的 `default_pc` + `default_wap`（274 个文件，附表 E），PHP 对照仍用 `php/` 的 `2023.1000.3051`。
- **模板与对照代码版本不同**：模板包是 2020 年的版本，Java 要对照的 PHP 代码是 2023 年的版本，二者的兼容性没有核实。已知的现象见附表 E.4：手机包的 `user/include.html` 用了 `{maccms:path}`、`{maccms:siteaid}`、`{maccms:sitetid}`、`{maccms:siteid}`，在 `php/application/` 里搜不到定义；官方包也不提供 `php/` 控制器会请求的全部页面（桌面 41 个、手机 57 个缺文件，见附表 B.1.1）。凡两边输出不同的地方，一律以 `php/` 的 `2023.1000.3051` 实际输出为准（BR-3）。模板目录配置是技术项，由架构设计决定，见 OP-15。
- 数据库约束早已存在并有测试守着：路线图 1.2 节“零结构变更”，`SchemaGuardTest` 静态扫描 DDL；本次发起人把它再次定为硬性约束。冲突点是：旧系统有几项功能本身要执行建表/改表语句（数据库工具的还原备份与执行 SQL、安装向导建库建表、插件自带 SQL），这几项按约束不能原样迁（见 FR-9、OP-6～OP-8）。
- 补充发现（v2）：旧后台“重复数据”功能（`admin/Vod.php:103-105`、`Art.php:51-53`、`Website.php:50-52`）会 `DROP/CREATE TABLE mac_tmp*`，同样违反“表不能动”；Java 已用子查询替代（`22-b13-admin-content.md` D-B13-7），本期不得退回 DDL，并由结构快照（SNAP-2）守护。
- 资料冲突与取舍：路线图 D4（jte 运行时编译在线编辑）与“模板以 PHP 模板为准”冲突；本文以发起人新口径为准，D4 作废（OP-3 已确认）。v5 的“同版本官方默认模板”与官方包实际内容冲突；本文以发起人 2026-10-31 的重新决定为准（OP-1）。

## 7. 功能需求
优先级：**P0** = 不做则“前台以 PHP 模板为准”无法成立；**P1** = 旧系统已有、Java 未覆盖或未验证、与 P0 无硬依赖；**P2** = 取决于你的决定，决定前不开发。依赖只描述技术先后，不构成开工授权。

### FR-1 模板包来源与放置（P0，所有前台项的前置）
- 入口：部署方按 OP-15 的决定放置模板包。
- 主流程：模板包固定为 MacCMS 官方 `v2020.1000.1035`（提交 `4c418c2703692148a937ad92893ab8a494bff742`）的 `template/default_pc`（桌面，147 个文件：`html/` 92、`ads/` 1、`css/` 4、`js/` 11、`images/` 38、`info.ini` 1）和 `template/default_wap`（手机，127 个文件：`html/` 76、`css/` 2、`js/` 9、`images/` 39、`info.ini` 1；**没有 `ads/`**），共 274 个文件，逐文件清单见附表 E。模板文件按官方原样使用，不改内容（BR-11）。静态资源（`css/js/images`）随包放置并能被前台请求到。旧配置项 `template_dir`、`html_dir`、`mob_template_dir`、`mob_html_dir`、`ads_dir`（`application/extra/maccms.php:34-38`）在 `php/` 里的基线值是 `default`、`html`，与官方包的目录名 `default_pc`、`default_wap` 不同；**这些配置项取什么值、包放在哪个目录、PHP 对照环境怎么配，本文不假设，由架构设计决定（OP-15）**。
- 异常与边界：配置指向的目录不存在或为空文件（如现在的 0 字节 `index.html`）时，前台返回与旧站“模板文件不存在”同等性质的错误页，且后台首页给出提示；不回退到别的模板，也不回退到 jte 页面（OP-3 已确认下线）。包内缺少某个页面文件时的表现见 BR-12。

### FR-9 数据库工具中会执行结构语句的四项（P2，OP-6 已确认）
- 旧功能：后台“数据库”的还原备份、执行 SQL、优化表、修复表（`admin/controller/Database.php:141-271`）。

### FR-10 安装向导的建库建表（P2，OP-7 已确认）

### FR-12 旧控制器功能对齐与缺口迁移闭环（P1；分两个阶段，两个阶段都完成才算本项完成）
