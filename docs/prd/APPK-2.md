## 1. 一句话定义
把旧 MacCMS（`php/`，PHP + ThinkPHP 5.0）还没迁到 Java 的功能继续迁完；前台页面的模板以 PHP 模板（MacCMS 标签语法的 `.html`）为准；全程不动数据库表结构，Java 按原表、原字段、原数据语义读写。

## 2. 背景与问题
- 现状（v6 清单已确认）：B01～B29 的 Java 代码大多已在 main，但前台页面是**重新写的 jte 页面**（`src/main/jte/site/…`），不是 PHP 模板；路线图当时的决定是“改写，不做兼容层”（`docs/architecture/09-roadmap.md` 第 2 节，03 草稿第 4.7 节“甲”方案）。
- 发起人 2026-10-30 的新方向与它冲突：前台模板要以 PHP 模板为准，也就是 Java 要能直接读取并渲染 MacCMS 模板（`{maccms:vod …}`、`{$obj.vod_name}`、`{include file=…}` 这类语法）。这在路线图里属于未做的“乙”方案（03 草稿第 4.7 节：兼容层，前期成本高）。
- **模板源文件目前不在仓库里**：`php/template/` 下只有一个 0 字节的 `php/template/default/html/index.html`；备份 zip 里也一样（`AGENTS.md` 第 15 行、`09-roadmap.md` D9-a）。没有模板，就无法开发，也无法验收。见 OP-1。
- 数据库约束早已存在并有测试守着：路线图 1.2 节“零结构变更”，`SchemaGuardTest` 静态扫描 DDL；本次发起人把它再次定为硬性约束。冲突点是：旧系统有几项功能本身要执行建表/改表语句（数据库工具的还原备份与执行 SQL、安装向导建库建表、插件自带 SQL），这几项按约束不能原样迁（见 FR-9、OP-6～OP-8）。
- 资料冲突与取舍：路线图 D4（jte 运行时编译在线编辑）与“模板以 PHP 模板为准”冲突；本文以发起人新口径为准，D4 怎么处理见 OP-3。

## 7. 功能需求
优先级：**P0** = 不做则“前台以 PHP 模板为准”无法成立；**P1** = 旧系统已有、Java 未覆盖或未验证、与 P0 无硬依赖；**P2** = 取决于你的决定，决定前不开发。依赖只描述技术先后，不构成开工授权。

### FR-1 模板包来源与放置（P0，所有前台项的前置）
- 入口：发起人提供模板包（OP-1）。
- 主流程：模板包放到 `template/<template_dir>/<html_dir>/` 约定目录（旧配置 `application/extra/maccms.php:34-38`：`template_dir=default`、`html_dir=html`；手机为 `mob_template_dir`、`mob_html_dir`、广告为 `ads_dir`），并包含该模板用到的静态资源（`/template/<dir>/` 下的 css/js/images）。Java 启动时按这三个配置项定位目录。
- 异常与边界：目录不存在或为空文件（如现在的 0 字节 `index.html`）时，前台返回与旧站“模板文件不存在”同等性质的错误页，且后台首页给出提示；不得回退到别的模板而不告知（回退策略见 OP-3）。
- 涉及规则：BR-2、BR-6。依赖：OP-1。

### FR-2 PHP 模板语法渲染（P0）
- 入口：前台任意页面请求。
- 主流程：Java 读取 `.html` 模板并按 ThinkPHP 5.0 “Think”模板引擎的语法渲染（`application/config.php:124-143`：标签起止符 `{` `}`，后缀 `html`，预加载 `app\common\taglib\Maccms` 标签库）。语法范围以**提供的模板包实际用到的写法**为准：变量输出 `{$a.b}`、函数调用 `{:fn()}`、`{include file=…}`、`{if}/{else}`、`{volist}`、`{foreach}`、`{for}`、`{php}`/`<?php` 等；具体清单由扫描模板包后列出，经你确认（OP-4）。
- 异常与边界：模板中出现未支持的语法或函数时，渲染失败的页面返回 500 并在日志写明模板文件名与行号；不得静默输出残缺页面。模板中的 `{php}`、`<?php` 代码块 Java 无法执行，默认不支持（OP-4）。
- 涉及规则：BR-3、BR-4。依赖：FR-1、OP-4。

### FR-3 Maccms 标签库（P0）
- 入口：模板中的 `{maccms:xxx …}…{/maccms:xxx}`。
- 主流程：实现 `php/application/common/taglib/Maccms.php` 的 19 个标签及其全部属性，查询结果与旧标签一致：
  - 内容类：`vod`、`art`、`topic`、`actor`、`role`、`website`、`comment`、`gbook`、`type`、`link`；
  - 筛选项类：`area`、`lang`、`class`、`year`、`version`、`state`、`letter`；
  - 控制类：`foreach`、`for`。
  - 属性例：`vod` 支持 `order,by,start,num,id,ids,not,paging,pageurl,type,typenot,class,tag,area,lang,year,level,letter,half,rel,version,state,tv,weekday,timeadd,timehits,time,hitsmonth,hitsweek,hitsday,hits,cachetime`（完整清单以 `Maccms.php:9-27` 为准）。
  - `Macdiy` 标签库只有一个调试用的 `test` 标签（`Macdiy.php`，输出后 `die`），不迁。
- 异常与边界：标签属性取值非法、结果为空、`paging=yes` 的分页、`cachetime` 缓存、`start/num` 越界时的表现，与旧版一致（以 PHP 黄金样本为准）。
- 涉及规则：BR-3、BR-5。依赖：FR-2；Java 侧已有的内部查询能力（B04/B05 已实现 `isend/timeadd/…` 等条件，见 `09-roadmap.md` 第 3.2 节第一行）可复用，但它们是否覆盖全部标签属性由 FR-12 核验。

### FR-4 模板函数与页面变量（P0）
- 入口：模板里 `{:mac_xxx(…)}`、`{$maccms.xxx}`、`{$obj.xxx}`、`{$GLOBALS['config']…}` 等。
- 主流程：①函数：`php/application/common.php` 里有 134 个 `mac_*` 函数，模板可能调用其中一部分以及 PHP 内置函数；**只实现模板包实际用到的**（扫描得出，OP-4），每个函数的返回值与旧版一致。②变量：每个页面模板可见的变量（如 `$maccms`、`$obj`、`$type`、`$param`、`$page` 等）的名称、层级和取值，与旧控制器 `assign()` 的结果一致（`common/controller/All.php` 的 `label_maccms()` 等）。
- 异常与边界：变量不存在时，输出与旧版一致（空串或报错，按黄金样本）。
- 涉及规则：BR-3。依赖：FR-2、OP-4。

### FR-5 前台页面接入 PHP 模板（P0；按页面类型分批，见 §13 顺序）
- 入口：§6 前台各页面类型的 URL（沿用 Java 已实现的旧 URL 生成与解析，`09-roadmap.md` 第 3.2 节）。
- 主流程：各页面的**数据与业务逻辑沿用 Java 现有实现**（B01～B11、B24～B26 等），改为把数据交给 PHP 模板渲染，而不是 jte 页面。模板文件选择规则与旧版一致：分类页用 `mac_type.type_tpl_list`、详情用 `type_tpl_detail`、播放/下载用 `type_tpl_play`/`type_tpl_down`；单条内容的 `vod_tpl`、`vod_tpl_play`、`vod_tpl_down`（文章/演员/角色/专题/网址同理，各自的 `*_tpl`）优先；字段为空时用旧版默认文件名。
- 异常与边界：404/无权限/观看密码/站点关闭/验证码错误等页面，用 §11 的表现；ajax 片段页返回与旧版相同的 HTML 片段（不是 JSON，`comment/ajax`、`gbook/ajax` 除外）。
- 涉及规则：BR-4、BR-7。依赖：FR-1～FR-4。

### FR-6 静态生成使用 PHP 模板（P1，依赖 FR-5）
- 入口：后台“生成”（`admin/make/*`，11 个方法）和定时任务 `make`。
- 主流程：生成的静态页内容用同一套 PHP 模板渲染，文件路径、命名规则沿用旧版（B16 已实现生成框架，`staticgen`）。
- 异常与边界：生成时模板渲染失败的页面记入失败列表，不中断整批；与旧版相同。
- 依赖：FR-5。

### FR-7 后台模板管理改为管理 PHP 模板文件（P1）
- 入口：后台“模板管理”（`admin/template/*`：列表、在线编辑、删除、标签向导、广告文件）。
- 主流程：列表和编辑针对 `template/<template_dir>/<html_dir>/` 下的 `html/htm/js/xml`（旧扩展名白名单，`Template.php:177` 一带）；保存后下一次请求生效；标签向导生成 **MacCMS 标签语法**片段（而不是 B15 里改写的 jte 片段）。安全过滤沿用旧规则（命中 `<?`、`php`、`eval` 等即拒绝，以旧代码为准）。
- 异常与边界：路径越出模板目录、扩展名不在白名单、内容命中过滤、并发保存（后保存者收到提示，B15 已有此约定，保留）。
- 涉及规则：BR-6。依赖：FR-1、OP-3（jte 编译回退机制是否保留）。

### FR-8 手机模板与语言包（P1）
- 入口：手机 UA/域名访问；`app.lang` 语言设置。
- 主流程：手机访问且满足旧选择条件（`mob_status`、`site_wapurl` 等；Java 已实现选择语义，`21-b12-admin-framework.md` 第 12 节、`SiteTemplateSelectionGoldenTest`）时，改用 `mob_template_dir/mob_html_dir` 下的 PHP 模板；模板中的 `{:lang('…')}` 取 `application/lang/zh-cn.php`、`zh-tw.php`。
- 异常与边界：手机模板目录缺失时的表现与旧版一致（旧版不回退到桌面模板，见 21 文档）。
- 依赖：FR-1（需要手机模板包，OP-1）、FR-2。

### FR-9 数据库工具中会执行结构语句的四项（P2，依赖 OP-6）
- 旧功能：后台“数据库”的还原备份、执行 SQL、优化表、修复表（`admin/controller/Database.php:141-271`）。
- 现状：Java 对这四项在入口拒绝并给固定提示（B15，D-B15-1）。
- 在“表结构不能动”下：还原备份会执行备份文件里的 `DROP TABLE/CREATE TABLE`，执行 SQL 可执行任意含 DDL 的语句，**与硬约束冲突，默认继续拒绝**；优化/修复是否算“动表”需你判断（OP-6）。
- 其余已迁部分不动：表状态列表、查看列、备份导出（只 `SHOW`/`SELECT`）、删除备份文件、批量替换（B15）。

### FR-10 安装向导的建库建表（P2，依赖 OP-7）
- 现状：Java 安装向导（B22）已实现，建库建表一步由部署方在库外导入 `install.sql`，向导只读校验。
- 在“表结构不能动”下：默认保持现状；本项只确认“继续如此”。

### FR-11 在线采集、远程图片下载、规则在线抓取、远程存储（P2，依赖 OP-5）
- 旧功能：E01 资源站在线采集（`admin/collect` 的在线抓取与定时任务 `collect`、`collect/timing` 页）、E02 远程图片下载、E03 自定义规则在线抓取、E08 远程存储（又拍/七牛/FTP/微博/阿里/Uomg）。
- 现状：2026-10-16 发起人 D1 决定只做本地版本（本地文件源/本地 HTML/本地存储），在线部分明确不实施；2026-10-28 又决定删除 `collect/timing` 与定时 `collect`（`27-b19-collect-ingest.md` D-B19-15）。
