### 结论摘要

1. **仓库不完整**【确认】：
   - 前台模板缺失，线上备份里也没有；`template/default/html/index.html` 是 0 字节。
   - `vendor/` 因为 `vendor/.gitignore` 是 `*` 而没有进入 git。
   - `extend/` 是空的。

   结果是本地只有后台能跑。前台实测的 3 个样本页（首页、分类页、会员登录页）都报"模板文件不存在"，其他前台页面没有逐一实测。
2. **在本仓库代码中发现了与重构无关的安全问题**，线上是否同样存在**待核实**：
   - 会员可以直接用 md5 哈希登录【本地实测】；
   - 会员可以只凭 openid 登录【本地实测】；
   - 定时任务接口没有鉴权【仅代码阅读，未实测】；
   - OAuth 自动建号用时间戳作为密码【仅代码阅读】。

   建议先核实线上；如果存在，另开任务在 PHP 端修复（需要用户确认）。
3. **选型**：两种语言都可行，架构上建议**模块化单体加独立采集 worker**，不做微服务。**语言不给无条件推荐**：仓库里没有团队、部署环境、流量和业务范围的证据，推荐要按用户对 02 第 5 节问题的回答，套用 02 第 4 节的条件分支；信号冲突时用 PoC 决定。"继续用 PHP 并加固"作为对照项列出。
4. **迁移**（草稿，全部是待实施的设计，未实现）：
   - 先沿用 `mac_*` 库，只做增量变更。
   - 按"表 + 操作"确定唯一写入方，切换前用 PHP 侧写入守卫（待批准）和数据库表级权限封住旧入口。
   - 顺序：只读前台 → Provide → 采集抓取（入库仍走 PHP 合并）→ 会员与互动（连同其后台页面）→ 内容写入与其余后台 → 下线 PHP。
   - 会员密码渐进升级，用"指纹"让 PHP 侧改密后的 v2 哈希自动作废；cookie 并行期按旧算法互通。
   - 回滚要先停新写入、排空、对账，再恢复旧方；耗时待演练。引擎和字符集转换存在不可逆边界。
