### 结论摘要

1. **仓库不完整**：
   - 前台模板缺失，线上备份里也没有；`template/default/html/index.html` 是 0 字节。
   - `vendor/` 因为 `vendor/.gitignore` 是 `*` 而没有进入 git。
   - `extend/` 是空的。

   结果是本地只有后台能跑，前台所有页面都报"模板不存在"。
2. **现网存在 3 个与重构无关的安全问题**，前两个已在本地实测确认：
   - 会员可以直接用 md5 哈希登录；
   - 会员可以只凭 openid 登录；
   - 定时任务接口没有鉴权。

   建议另开任务，先在 PHP 端修复（需要用户确认）。
3. **选型**：两种语言都可行，推荐**模块化单体加独立采集 worker**，不做微服务。
   - 在没有其他信息时，**弱倾向 Go**（内容站加采集，运维轻）。
   - 如果团队以 Java 为主，或者会员、支付业务要扩展，选 **Java**。
   - "继续用 PHP 并加固"作为对照项列出，供用户决策。
   - **语言未定**，需要用户先回答 02 第 5 节的问题。
4. **迁移**：先沿用 `mac_*` 库，只做增量变更；nginx 按路由灰度；顺序是"只读前台 → Provide → 采集 → 会员/互动 → 后台"；会员密码渐进升级，并行期保留 md5 列以便回滚；旧 URL 用黄金样本逐条对比。
