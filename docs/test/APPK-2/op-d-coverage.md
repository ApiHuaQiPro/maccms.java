## 0. 读法与三个先决说明

**PRD 对 `排除-` 的规定（FR-12、AC-14）**：`排除-<OP-n 或 D 编号>` 须该 OP- 已「移出本期」，或 D 编号是已确认的历史决定；`缺口` 行必须在 `gap-register.md` 有 GAP-。

1. **「已确认」不等于「移出本期」。** PRD §14 里 OP-1～OP-14 的状态都是「已确认→写入 FR-/BR-/AC-」，意思是把答案写进了需求，功能照做；没有一条写「移出本期」。所以 **`排除-OP-n` 目前一个都不能用**。OP-6（数据库工具四项）、OP-7（安装只执行原版 `install.sql`）、OP-5（在线功能）改变的是「这一行的判定基线」，不是把行排除出去（见 §4）。
2. **D2 的写法有出处。** 技术设计 §6.16 明文要求：六项安全修复（SEC-1～6）判 `排除-D2`；D2 是路线图 §9 用户 2026-10-16 的已决事项，OP-9（评论 `01a19127-560b-7df6-abfd-0c7672cd5643`）又重申「6 项安全修复全部保留」。这符合 AC-14 的「D 编号是已确认的历史决定」。
3. **`排除-SEC-7` / `排除-SEC-9` 与 AC-14 字面不一致（待调度确认，见 `gap-register.md` 的 GAP-M6）。** 技术设计 §6.16 要求这两项判 `排除-SEC-7` / `排除-SEC-9`，但 SEC-7、SEC-9 不是 PRD 的 OP-n，也不是路线图的 D 编号；它们的决定来源是技术设计的 OP-T5=a、OP-T4=a（发起人确认评论 `01a194e9-23e8-7682-8ae5-b7c5e19b0040`）。我不改 PRD，也不替调度裁定写法；在调度确认前，测试人员这两类样本只写「待确认写法」，不填 PASS。
4. **部分差异不等于整行排除。** 六项安全修复和 SEC-9 都只在「差异样本」上与 PHP 不同（例如观看密码只有「超限」样本不同）。引用 `排除-D2` 只覆盖该差异点的样本，同一行其余样本仍须按 `✅已对齐`（附 Java 类/方法与测试名）判。一行只能有一个最终取值时，以「该行是否还有未被排除的 PHP 行为」为准：有，就不能写成整行 `排除-`。
