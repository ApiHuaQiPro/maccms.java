# Content · 用例设计标准（T1 + 接口用例）

## 适用
- **T1 功能用例**：G0 后，依据 PRD 的 AC- + 技术设计 + UI 设计（有设计环节的档位以 G1 通过的版本为准）。
- **接口用例**：API 契约通过复核后，依据契约文件（路径 + 提交号），与开发并行。
- **bug-fix 档**：把 Issue 的复现步骤写成回归用例（追溯写该 Issue 的 AC-），再补受影响功能的回归用例。
- **T2 补充用例**：同一套模板与清单（见 `multica-test-t2-coverage`）。
- 只写不执行；“只写”的边界见 `multica-test-orchestration`。

## Step 1 · 追溯矩阵（写用例之前）
- 验收分母只认当前 Issue / PRD 的 AC-。设计里有、AC- 没有的 → 只进“关注点”，不进验收。
- 冲突优先级：Issue AC- > PRD > 技术设计 / API 契约 > UI 设计。发现冲突 → 列出来交 Leader，不自行裁决。
- 缺 AC- 原文 → BLOCKED。缺设计 → 矩阵里写明“无设计，仅按 AC- 写”，不编造设计点。

```markdown
## 追溯矩阵 — <ISSUE-KEY>
| AC- | 来源（PRD 章节 / 设计章节 / DESIGN-ID / 接口） | 覆盖维度 | 用例编号 | 备注 |
| --- | --- | --- | --- | --- |
| AC-1 | PRD §3 / tech-design §4 / D-03 / POST /api/orders | 正常、边界、权限 | TC-F-ORDER-001…003、TC-I-ORDER-001 | |

## 关注点（设计有、AC- 无，不计入验收）
## 回归范围（技术设计影响面里受波及的既有功能）
```

## Step 2 · 覆盖维度（每个模块逐项过；不适用写一句原因）
| 维度 | 必须覆盖 | 何时可跳过 |
| --- | --- | --- |
| 正常 | 主路径 + 每个正向分支各一次 | 不可跳过 |
| 边界 | 每个输入：最小 / 最大 / 越界一档、空、超长、格式错；分页、时间、文件、数量上限 | 无输入、无限制 |
| 异常 | 服务报错、资源不存在、超时、重复提交、当前状态不允许的操作 | 不可跳过 |
| 权限 | 未登录、无权限角色、只读角色写操作、横向越权（读改他人数据）、纵向越权（低权限调高权限操作） | 无鉴权的公开功能 |
| 安全 | 按 `multica-review-security` 的类别挑与本 Issue 相关的，写成可执行用例（下手方法见细项清单） | 写明不相关原因 |
| 回归 | 影响面里的既有功能各一条主路径；每个已修复缺陷一条 | 全新且无依赖的功能 |
| 页面状态 | 设计稿给出的六态（正常 / 加载 / 空 / 错误 / 禁用 / 无权限）与交互态 | 无界面改动 |

- 规模：小需求（1–2 个功能点）写核心正常 + 关键异常 / 权限 / 边界，不发散；大需求不得漏维度。条数不设上限，以覆盖 AC- 为准。
- 去重：同模块、同场景、同操作路径只写一次；等价的反向样本可合并成一条（预期里逐个列出），失败后无法定位根因的关键边界单独成条。
- 细项（每个维度具体想到哪些点）：[`references/coverage-checklist.md`](references/coverage-checklist.md)。

## Step 3 · 写用例
### 功能用例（TC-F）
```text
用例编号: TC-F-<模块>-<序号>
模块:     <系统/业务域/功能，用 / 分层>
标题:     <场景一句话>
维度:     正常 | 边界 | 异常 | 权限 | 安全 | 回归 | 页面状态
优先级:   P1 | P2 | P3
追溯:     AC-<n>（回归用例写被保护的功能或 BUG-<n>）
自动化:   UI | 接口 | 手工（手工须写原因；T3 中手工用例记 BLOCKED 交人工验证）
前置:
  1. 登录具备【<模块/操作>】权限的测试账号（只写权限语义，不写账号与密码）
  2. 测试数据：<别名>=<关键字段取值>
步骤:
  1. 进入 <系统> → <菜单路径>，等待加载完成
  2. <操作>
预期:
  1. <对应步骤 1 的即时结果>
  2. <对应步骤 2 的可判定结果>
```

### 接口用例（TC-I）
```text
用例编号: TC-I-<模块>-<序号>
接口:     <METHOD> <路径>（API-ID <id>；契约 docs/api/<ISSUE-KEY>/openapi.yaml @ <提交号>）
标题 / 维度 / 优先级 / 追溯: 同功能用例
前置:     鉴权：<角色>的令牌，取自环境变量 <变量名>（以 MULTICA.md §5 为准）；测试数据别名
请求:     <参数与取值；敏感值写“<来自环境变量 X>”>
预期:     状态码 <n>；业务码 <n>；字段 <逐项：存在 / 类型 / 取值 / 格式>；不得出现 <契约外敏感字段>
```

### 规则
- 优先级：P1 = 核心主路径 + 安全 / 越权；P2 = 一般路径、页面状态、回归；P3 = 其余异常与边界。不用 P0。
- 步骤与预期一一对应、条数相等；一步内多个验证点用 `1）2）` 写在同一条预期里。
- 预期写即时、可判定的结果；禁用“应该 / 可能 / 正常显示 / 符合预期”等含糊词。
- 菜单路径、字段、文案来自 PRD / 设计 / 契约，不臆造；拿不准的写“以页面实际文案为准”并在矩阵备注。
- 测试数据用别名 + 关键字段值，邮箱用 `example.com` 保留域名；不写真实个人信息。

## 用例自检清单（★唯一一份，@Tester 自查与 @TestReviewer 评审共用★）
每条写依据（用例编号 / 矩阵行 / 文件路径）；没有依据不得打勾。
### 用例
- [ ] 每条 AC- 都在追溯矩阵里，且至少一条正向 + 一条反向用例；没有 AC- 之外的“验收点”
- [ ] 每个模块的七个维度都已覆盖，或写明跳过原因
- [ ] 有鉴权时：未登录、无权限、只读写操作、横向越权、纵向越权各有用例
- [ ] 与本 Issue 相关的安全类别都有用例，或写明不相关原因
- [ ] 影响面中的既有功能有回归用例；已修复缺陷各有一条回归用例
- [ ] 步骤与预期一一对应、条数相等；预期可判定，无含糊词
- [ ] 前置只写权限语义与测试数据别名；无账号、密码、令牌、真实个人信息；无 XXX / TBD / 待补充 等占位
- [ ] 菜单路径、字段、文案有出处，不臆造
- [ ] 接口用例与 API 契约逐项一致（路径、方法、参数、状态码、错误码、字段）
- [ ] 每条用例标了自动化通道；标“手工”的写明原因
- [ ] 编号唯一；模块用 / 分层；优先级符合规则
### 脚本（接口用例阶段 / T2）
- [ ] 标“UI / 接口”的用例与测试函数一一对应（1 CASE = 1 test），静态收集数相等
- [ ] 脚本与配置无账号、密码、令牌、Cookie 字面值；只读 MULTICA.md §5 登记的变量名
- [ ] 每条预期都有对应断言；无空断言、吞异常、为稳过删步骤
- [ ] 只写未执行：产物里没有对任何环境的执行结果

## 产物与位置
- `docs/test/<ISSUE-KEY>/t1-cases.md`：追溯矩阵 + 关注点 + 回归范围 + 功能用例 + 自检记录（按上表逐条写依据）
- `docs/test/<ISSUE-KEY>/api-cases.md`：接口用例 + 自检记录
- 接口自动化脚本：按 `multica-test-t3-api-automation` 写在 MULTICA.md §2 的 API 用例路径
- 回传：按 `multica-test-orchestration` 的回传规范
- 只有 Issue 或 MULTICA.md 明确要求把接口用例同步到接口平台时，才经 `multica-platform-apifox`；它当前未接入，按其说明报 BLOCKED，仓内用例与脚本照常交付

# 覆盖细项（写用例时逐维度过）

> 维度定义、取舍与规模规则见 `../SKILL.md`。这里列“每个维度具体想到哪些点”。不是每项都要写用例：与本 Issue 相关的才写，不相关的在追溯矩阵里一句话说明。

## 正常与分支
- 主路径完整走通；每个条件分支、每个下拉 / 单选 / 多选的选项值各一次
- 状态流转：正向、回退、跳过中间态、已结束状态再操作
- 数据联动：新增后列表更新、编辑后关联字段刷新、删除后关联数据变化
- 组合：多条件筛选、排序 + 分页 + 筛选、批量操作 + 选择项

## 边界（每个输入控件 / 参数）
| 类型 | 要测的点 |
| --- | --- |
| 数值 | 最小、最大、最小 - 1、最大 + 1、0、负数、小数精度 |
| 字符串 | 空、1 个字符、最大长度、最大长度 + 1、纯空格、特殊字符、emoji 与多语言、换行 |
| 列表 | 空、1 个、上限、上限 + 1 |
| 枚举 | 每个值一次、不存在的值、空值、类型错（数字 / 字符串） |
| 时间 | 当前、过去、未来、闰日、跨时区、非法日期（如 2 月 30 日）、空 |
| 文件 | 0 字节、刚好等于上限、超上限、不支持的格式、文件名含特殊字符、损坏文件 |
| 分页 | 第一页、最后一页、0 或负数、超过总页数、每页 1 条、每页上限、超上限 |
| 必填与唯一 | 全空、只填部分、只填空格；重复提交、并发创建、改成已存在的唯一值 |

## 异常
- 服务端报错、资源不存在、超时、依赖服务不可用（只在测试环境能制造时写）
- 重复点击提交、浏览器回退后再操作、多个标签页同时改同一条数据
- 错误提示用户看得懂，不出现堆栈、SQL、内部路径、英文技术报错

## 权限（有鉴权时必过）
- 未登录直接访问页面和接口
- 已登录但没有该权限的角色
- 只读角色尝试写操作
- 横向越权：A 用户读 / 改 / 删 B 用户的数据（改 URL 或参数里的 ID）
- 纵向越权：普通用户调用管理接口、直接打开管理页面
- 前端隐藏的按钮，其背后的接口要用低权限令牌直接调一次（只藏按钮不等于有鉴权）

## 安全（类别以 `multica-review-security` 为准；这里只写测试怎么下手）
- 注入与 XSS：在输入框和参数里放 `' OR 1=1--`、`<script>alert(1)</script>`、`<img src=x onerror=alert(1)>`；预期被拒绝或原样转义显示，不执行、不报数据库错误
- 敏感信息：响应、页面源码、错误信息、导出文件里不出现密码（含哈希）、令牌、完整证件号 / 手机号等契约外字段
- 登录 / 找回类提示不泄露账号是否存在（统一“账号或密码错误”）
- 限流：契约有约定时，短时间重复请求触发限流
- 会话：有退出功能时，退出后旧令牌、旧页面不可再用
- 文件上传：改扩展名伪装的可执行文件、超大文件、文件名含 `../`；预期被拒绝
- CSRF：使用 Cookie 会话时，写操作缺少防跨站校验应被拒绝
- 接受 URL 的参数：传内网地址（如 `127.0.0.1`），预期被拒绝
- 所有安全用例只用测试数据、只对测试环境，不用破坏性载荷（删数据、大量写入）；不对其他地址做任何尝试

## 回归
- 技术设计“影响面”里的既有功能：各至少一条主路径用例
- 公共组件、共享接口、数据迁移改动：每个调用方一条
- 每个已修复缺陷：把复现步骤写成一条回归用例（追溯写 BUG-<n>）

## 页面状态与检查（定性，不量像素）
- 设计稿六态：正常 / 加载 / 空 / 错误 / 禁用 / 无权限，各自的出现条件与文案
- 交互态：悬停、焦点、校验错误提示的出现位置与文案
- 元素完整：按钮、输入框、文案、链接存在且正确，无残留元素
- 响应式：设计稿三档宽度下不塌版、无横向滚动
- 键盘：Tab 顺序合理、回车触发主操作、焦点可见
- 不测精确像素、色值、圆角（那是 @DesignReviewer 看截图的职责）

## 接口（按契约逐项）
| 场景 | 要测的点 |
| --- | --- |
| 成功 | 状态码、业务码；字段齐全无多余；类型与格式（日期、金额、URL、枚举拼写） |
| 参数 | 必填缺省、类型错、格式错、空值 / null、超长、越界、不存在的枚举、多余参数、缺请求头 |
| 鉴权 | 无令牌 → 401；无权限 → 403；访问他人资源 → 403 或 404（按契约） |
| 资源 | 不存在 → 404；重复创建 → 契约约定码；删除后再读 |
| 列表 | 默认分页、指定分页、越界分页、排序、筛选、空结果 total = 0 |
| 写操作 | 重复提交同一请求（幂等）、并发写、失败后无脏数据 |
| 错误响应 | 结构统一；不含堆栈、SQL、内部路径 |

逐字段校验顺序：存在 → 类型 → 取值范围 → 边界 → 空值（null / "" / [] / 缺省，按契约）→ 格式。
